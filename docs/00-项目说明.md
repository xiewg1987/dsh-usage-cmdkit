## 一、项目是什么

DSH 第三方插件：在 Web 侧边栏展示 **本地 Token 用量 Dashboard**。
- 数据来自 harness 已有的 session/turn usage，不额外调模型
- Host 写 `usage-stats.json`；Client 通过 remotes 读聚合

## 三、核心概念（简洁版）

| 对象 | 说明 |
|------|------|
| `TurnTokenUsage` | 四桶精确统计：`uncachedInputTokens`、`outputTokens`、`cacheReadTokens`、`cacheWriteTokens` |
| `SessionEvent` | DSH 事件流：`turn/start` → `step/start` → `assistant/attempt` → `assistant/message` → `turn/end` |
| `deriveTurnTokenUsage` | 核心函数：把 turn 事件流折叠成精确 token 统计（来自 `@deepseek-ai/dsh-token-meter/client`） |

> **为什么要用 turn 边界？** 一个 turn 可能有多次 attempt/retry，直接按 `message` 加会重复或漏计。

## 四、步骤1 代码详解（重点）

### 4.1 文件位置
`src/index.ts`（当前仅骨架，需实现步骤1）

### 4.2 需要引入的类型和函数

```typescript
import type { Context } from '@deepseek-ai/cordis'
import type { Session } from '@deepseek-ai/dsh-session'
import type { SessionEvent } from '@deepseek-ai/dsh-session/types'
import { deriveTurnTokenUsage } from '@deepseek-ai/dsh-token-meter/client'
```

**解释**：
- `Context`：Cordis 上下文，用于 `ctx.on('session/event', ...)`
- `Session`：会话对象（含 `session.id`）
- `SessionEvent`：事件类型（含 `turn/start`、`turn/end` 等）
- `deriveTurnTokenUsage`：核心统计函数

### 4.3 TurnBuffer 接口（缓冲区定义）

```typescript
interface TurnBuffer {
  turn: number          // 当前 turn 编号
  events: SessionEvent[] // 收集的事件数组
}
```

**作用**：每个 session 一个缓冲区，临时存储从 `turn/start` 到 `turn/end` 的所有事件，等待统计。

### 4.4 turnOf 辅助函数

```typescript
function turnOf(event: SessionEvent): number | undefined {
  if (event.type === 'turn/start' || event.type === 'turn/end') return event.data.turn
  if ('turn' in event.data && typeof event.data.turn === 'number') return event.data.turn
  return undefined
}
```

**作用**：提取事件所属 turn 编号，确保只处理当前 turn 的事件，过滤无关事件。

### 4.5 apply 主入口

```typescript
export const name = 'usage-dashboard'

export function apply(ctx: Context): void {
  const buffers = new Map<string, TurnBuffer>() // sessionId -> 缓冲

  ctx.on('session/event', (session: Session, event: SessionEvent) => {
    const id = session.id

    // 1. turn/start：初始化缓冲区
    if (event.type === 'turn/start') {
      buffers.set(id, { turn: event.data.turn, events: [event] })
      return
    }

    // 2. 无缓冲区：跳过
    const buf = buffers.get(id)
    if (buf === undefined) return

    // 3. 校验 turn 一致性：事件 turn 必须与缓冲 turn 一致
    const t = turnOf(event)
    if (t !== undefined && t !== buf.turn) return

    // 4. 追加事件到缓冲
    buf.events.push(event)

    // 5. 只处理 turn/end
    if (event.type !== 'turn/end') return

    // 6. 调用核心函数统计
    const usage = deriveTurnTokenUsage(buf.events)
    buffers.delete(id) // 清理缓冲

    // 7. 错误处理：无法安全统计时 log 警告，不写 0
    if (usage === undefined) {
      console.warn(`[usage-dashboard] turn ${event.data.turn} session ${id}: no usage`)
      return
    }

    // 8. 成功：打印结果（与 Web「本轮用量」对照）
    console.log('[usage-dashboard] turn usage', {
      sessionId: id,
      turn: event.data.turn,
      ...usage,
    })
  })
}
```

### 4.6 关键逻辑逐行解释

| 行 | 代码 | 解释 |
|---|---|---|
| `buffers = new Map()` | 使用 Map 存储每个 session 的缓冲区，键为 `session.id` |
| `ctx.on(...)` | 监听 DSH 的 `session/event`，每次会话事件触发 |
| `turn/start` | 初始化缓冲，`events` 第一个元素就是 `turn/start` 事件 |
| `buf === undefined` | 如果没有正在进行的 turn，直接跳过（避免误处理） |
| `turnOf(event)` | 提取事件的 turn 编号，确保只收集当前 turn 事件 |
| `t !== buf.turn` | 如果事件属于其他 turn，跳过（防止跨 turn 污染） |
| `buf.events.push(event)` | 收集所有属于当前 turn 的事件 |
| `deriveTurnTokenUsage(buf.events)` | **核心**：把完整事件流折叠成 `TurnTokenUsage` |
| `buffers.delete(id)` | turn 结束后清理缓冲，为下一轮准备 |
| `usage === undefined` | 统计失败（事件流不完整、数据矛盾等），只 log 警告 |
| `console.log(...)` | 成功时打印，内容与 Web「本轮用量」四桶一致 |

### 4.7 为什么要这样写（设计原理）

1. **按 turn 边界**：只有在 `turn/end` 时调用 `deriveTurnTokenUsage`，避免多次统计同一 turn
2. **缓冲模式**：先收集所有事件再一次性统计，比每条消息单独加更准确（处理 retry、多 attempt）
3. **失败闭合**：如果函数返回 `undefined`，说明事件流不完整或数据矛盾，必须 log 而不是写假的 0
4. **不写文件**：步骤 1 只要求 log，落盘是步骤 2

## 八、常见问题与注意事项

| 问题 | 原因 | 处理 |
|------|------|------|
| `deriveTurnTokenUsage` 返回 `undefined` | 事件流缺 `turn/end`、多 turn 混合、数据矛盾 | 检查完整事件序列；参考 `tests/turn-usage.spec.ts` |
| log 不打印 | `session/event` 监听未正确绑定，或 `apply` 未执行 | 确认 `patch.dev.yml` 已插入 `usage-dashboard` |
| token 与 UI 不一致 | 缓存计算不同（部分 provider 无 cache 字段） | 确保四桶数据完全对齐，缺项用 0 |
| 多轮对话数据覆盖 | 缓冲区未清理，或 `turnOf` 校验失败 | 检查 `buffers.delete(id)` 是否执行 |
