## 一、项目是什么

DSH 第三方插件：在 Web 侧边栏展示 **本地 Token 用量 Dashboard**。

- 数据来自 harness 已有的 session/turn usage，不额外调模型
- Host 写 `usage-stats.json`；Client 通过 **Connection 认证路由** 读聚合

## 二、实施顺序（三步均已实现）

| 步骤 | 内容 | 状态 | 落点 |
|------|------|------|------|
| **1** | 获取统计：`session/event` → `deriveTurnTokenUsage` | ✅ | `src/turn-events.ts`、`src/index.ts` |
| 2 | 持久化：写入 profile 下 JSON，按日 rollup + 30 天 prune | ✅ | `src/usage-store.ts` |
| 3 | 数据通道 + Client Dashboard | ✅ | `src/host-routes.ts`、`src/client/` |

## 三、核心概念

| 对象 | 说明 |
|------|------|
| `TurnTokenUsage` | 四桶精确统计：`uncachedInputTokens`、`outputTokens`、`cacheReadTokens`、`cacheWriteTokens` |
| `SessionEvent` | DSH 事件流：`turn/start` → `step/start` → `assistant/attempt` → `assistant/message` → `turn/end` |
| `deriveTurnTokenUsage` | 核心函数：把 turn 事件流折叠成精确 token 统计（来自 `@deepseek-ai/dsh-token-meter/client`） |

> **为什么要用 turn 边界？** 一个 turn 可能有多次 attempt/retry，直接按 `message` 加会重复或漏计。
>
> **为什么必须从 `turn/start` 开始？** `deriveTurnTokenUsage` 是「失败闭合」的：
> 事件段里出现 `turn/start` 之前的事件、或 `turn/end` 之后的事件，它一律返回 `undefined`。
> 所以段必须恰好是 `turn/start`（含）… `turn/end`（含）。

## 四、步骤 1 实现：事件流上的 turn 收集器

### 4.1 为什么不用 `session.snapshotEvents()`

harness 已弃用 `session.eventAt()` / `session.snapshotEvents()` / `session.ownEvents()`
（决策：`.agents/notes/implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.zh.md`）：
存储的演进方向是不再把完整事件序列保存在内存里，**禁止新增生产调用**。

于是本插件改成**只消费 `session/event` 推送的事件**：在 `turn/start` 处开缓冲，
在 `turn/end` 处交出。内存占用与 turn 长度成正比，与会话历史长度无关。

### 4.2 收集器

`src/turn-events.ts`：

```typescript
export class TurnCollector {
  private readonly buffers = new Map<string, TurnBuffer>()

  push(sessionId: string, event: SessionEvent): SessionEvent[] | undefined {
    if (event.type === 'turn/start') {
      this.buffers.set(sessionId, { turn: event.data.turn, events: [event] })
      return undefined
    }

    const buffer = this.buffers.get(sessionId)
    if (buffer === undefined) return undefined

    const turn = turnOf(event)
    if (turn !== undefined && turn !== buffer.turn) return undefined

    buffer.events.push(event)
    if (event.type !== 'turn/end') return undefined

    this.buffers.delete(sessionId)
    return buffer.events
  }
}
```

| 行为 | 原因 |
|------|------|
| `turn/start` 覆盖旧缓冲 | 上一个 turn 没等到 `turn/end` 就不再补记；新 turn 优先 |
| 缓冲按 `session.id` 分开 | 多个会话（含子智能体会话）的事件流是交错的 |
| `turnOf(event) !== buffer.turn` 的事件丢弃 | 防御跨 turn 污染——混进去会让统计失真 |
| `turn/end` 交出后立刻 `delete` | 缓冲不跨 turn 存活，内存有界 |
| 收不到 `turn/start` 就丢弃事件 | 插件加载晚于 turn 起点时无法安全统计，不猜 |

### 4.3 Host 入口

`src/index.ts`：

```typescript
export const inject: string[] = []

export function apply(ctx: Context): void {
  // 路由要挂在 Connection 的认证通道里；没有 Connection 时不注册路由，但采集照常。
  ctx.inject(['connection'], (child) => {
    registerUsageRoutes(child)
  })

  const collector = new TurnCollector()

  ctx.on('session/event', (session: Session, event: SessionEvent) => {
    const slice = collector.push(session.id, event)
    if (event.type !== 'turn/end') return

    const usage = deriveTurnTokenUsage(slice)
    if (usage === undefined) {
      console.warn(`[dsh-usage-cmdkit] session ${session.id} turn ${event.data.turn}: 无结果`)
      return
    }

    void persistTurnUsage(usage, event.time).then(/* … 落盘 … */)
  })
}
```

### 4.4 失败闭合

`deriveTurnTokenUsage` 返回 `undefined` 的常见原因：

- 事件流缺 `turn/start` 或 `turn/end`
- attempt 的 usage 不完整（缺 `inputTokens` / `outputTokens`）
- `totalTokens` 与 `input + cacheRead + cacheWrite` 矛盾
- provider 没有同时给出 `cacheReadTokens` 与 `cacheWriteTokens`

这时**只 log 警告，不写 0**——写假的 0 会让 Dashboard 看起来比实际更准。

## 五、步骤 2：持久化

- 读写 profile 下 `usage-stats.json`（`$DSH_PROFILE_DIR`，否则 Harness home 的 `profiles/web`）
- 结构：按本地日 `YYYY-MM-DD` rollup，字段与步骤 1 相同；`byProvider` 键为 `provider/model`
- 每次 merge 后按**本地日历日**裁剪保留窗口外的日键（`retentionDays` 默认 30）
- 读-改-写走一条串行写链，写临时文件后 `rename` 原子替换

细节见 [02-persist-stats.md](./02-persist-stats.md)。

## 六、步骤 3：数据通道 + Client

- **不用官方 remotes**：Client 侧只装配 `@deepseek-ai/dsh-api-remotes`，
  那份清单是 harness 内部包的静态 import，第三方包加不进去；Remote 客户端还要求
  typert 生成的 `lib/typert.remote-client.*`。
- **改用 Connection 精确路由**：`ctx.connection.fetch.register` 注册
  `GET /api/usage.summary` 与 `POST /api/usage.clear`，浏览器同源 `fetch` 直读。
- **Client**：右栏 Tab（`ctx.sidebarRightTabs.register` + `sidebar.right.pane.tab` seat），
  内联样式，独立 esbuild 打包成 `lib/client.js`。

细节见 [03-remotes-and-client.md](./03-remotes-and-client.md)。

## 八、常见问题与注意事项

| 问题 | 原因 | 处理 |
|------|------|------|
| `deriveTurnTokenUsage` 返回 `undefined` | 事件段不完整、usage 矛盾、缓存桶缺失 | 看终端打印的事件类型序列 |
| log 不打印 | `session/event` 监听未绑定，或 `apply` 未执行 | 确认 `patch.dev.yml` 已插入 `dsh-usage-cmdkit` |
| token 与 UI 不一致 | 缓存计算不同（部分 provider 无 cache 字段） | 四桶缺项按 0；缺桶时 `deriveTurnTokenUsage` 会失败闭合 |
| 多轮对话数据覆盖 | 缓冲未清理 | `turn/end` 之后 `buffers.delete(id)` 必须执行 |
| 旧日键一直留着 | prune 按条数裁剪 | 已改为按本地日历日裁剪（见步骤 2 文档） |
| 浏览器半 404 / 加载失败 | 没跑 `pnpm run build:client` | `lib/client.js` 是产物，不入库 |
